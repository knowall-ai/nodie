== Installation

Requires Node.js 22 or later, npm, a desktop/browser with microphone access, and configured voice services. Docker access is optional for update monitoring; do not grant Docker access to an untrusted account.

[source,bash]
----
npm ci
cp .env.example .env
# Configure the endpoints and voice mode in .env.
npm test
npm start
# Alternative, loopback browser:
npm run web
----

The browser defaults to `http://127.0.0.1:8095`. Keep its server running, or use the documented user-service launcher. In local mode, click the microphone to enable continuous conversation; after detected speech, 900 ms of silence submits automatically. After a reply, listening resumes automatically. The mic button or a spoken microphone-off request ends the loop. Clicking the avatar while recording submits early; clicking it during processing/playback cancels. Audio is capped at 30 seconds and 5 MB. To change a voice control, address her by name: for example, “Nodie, mute yourself” or “Nodie, stop listening”. She interprets natural wording such as “Hey Nodie” or “Could you mute yourself, Nodie?” and likely transcription mistakes in her name. If the intended addressee or action is unclear, she should ask for clarification. Ordinary questions do not require the name; this does not wake a muted microphone.

=== Ubuntu sandbox

On Ubuntu systems restricting unprivileged user namespaces, Electron may need an application-specific AppArmor profile. Review and run `bash scripts/setup-linux-sandbox.sh`; administrator authentication is required. The script installs the `nodie-dev` profile (`/etc/apparmor.d/nodie-dev`), which permits user namespaces for this checkout's Electron executable only. It does not disable Chromium's sandbox or change the global kernel policy. Re-run after moving the checkout. The web interface is available without this change.

=== Packaged Linux install (.deb)

Each version tag (`v1.2.3`, matching `package.json`) runs `.github/workflows/release.yml` on Ubuntu 24.04. The workflow builds `nodie_<version>_amd64.deb` with `npm run dist` and checks it with `npm run dist:check`, then publishes it with `SHA256SUMS`. The check confirms the package name, the `/opt/nodie` payload and the AppArmor profile. It also refuses group- or world-writable entries, environment files, keys and likely credentials. To build locally, run `npm ci && npm run dist && npm run dist:check`.

The package installs root-owned files to `/opt/nodie` and links `/usr/bin/nodie`. It also installs a desktop entry (`StartupWMClass=nodie`). Its post-install script installs `/etc/apparmor.d/nodie`, granting user namespaces only to `/opt/nodie/nodie`, so Chromium's sandbox works without `--no-sandbox`. A checkout's `nodie-dev` profile from `scripts/setup-linux-sandbox.sh` can coexist with the package's profile. Older versions of that script named their profile `nodie`; installing the package replaces it. Install with `sudo scripts/install-system.sh nodie_<version>_amd64.deb <sha256>`, taking the SHA256 from the release's `SHA256SUMS`. The script verifies the hash on a root-owned copy and checks the package name, `/opt/nodie` payload and AppArmor profile. It removes the package again if the profile did not install.

The packaged binary's Electron fuses disable `ELECTRON_RUN_AS_NODE`, `NODE_OPTIONS` and inspector arguments, because its AppArmor profile grants user namespaces. Reverie memory therefore runs in an Electron utility process instead of a re-executed Node runtime. Semantic embedding libraries are not packaged; the desktop always uses keyword recall (`REVERIE_EMBEDDINGS=none`).

Launch with `/usr/bin/nodie` (or `/usr/bin/nodie --fullscreen --keep-awake` for an always-on TV display); the window class is `nodie`. TV mode uses a normal, non-dock window that stays fullscreen. A second launch shows and focuses the existing window without recreating it, and applies `--keep-awake` idempotently if supplied. Forwarding `--fullscreen` to a non-TV instance logs a restart notice and displays it where desktop notifications are supported; quit and restart with `--fullscreen` to enter TV mode. Later launches without flags do not disable TV mode or keep-awake. Settings, history and logs stay in `~/.config/nodie`. A packaged build reads `~/.config/nodie/.env`; a checkout keeps reading its own `.env`. `NODIE_ENV_FILE` overrides both. Crash minidumps are written locally to `~/.config/nodie/Crashpad` and are never uploaded.

`NODIE_EVENTS_DIR` moves the event journal and node status files that the backend's `compose.events.yml` reads. The default is `~/.config/nodie/events`. Set an absolute path, for example `/var/lib/nodie/events` on a host where the voice backend runs under another account. Face recognition in a packaged build needs `NODIE_FACE_PYTHON` to point at a separately prepared Python environment, because the package contains no virtual environment.

=== Configuration

`VOICE_MODE=local` selects the lightweight path. Set `LOCAL_STT_URL`, `LOCAL_STT_MODEL`, `LOCAL_TTS_URL`, `OLLAMA_URL` and `LOCAL_LLM_MODEL`. The selected local model is `qwen3.5:9b` (download with `ollama pull qwen3.5:9b`); set `LOCAL_LLM_MODEL=qwen3.5:9b`. Its voice requests disable thinking. Camera input remains a separate, unimplemented capability. The speech service must implement `/api/tts` returning WAV; the transcription service must implement `/v1/audio/transcriptions`.

Realtime mode requires `UNMUTE_BACKEND_URL`, `LLM_MODEL` and `VOICE_MODEL`. Keep dedicated speech models stopped when unused on constrained hosts. Nod.ie does not automatically start them.

=== Documentation build

Install the Ruby gems listed in `docs/Gemfile`, then run `npm run docs`. The build produces only `docs/TECHNICAL_SOLUTION_DOCUMENT.pdf`; do not commit it. Source sections and the branded theme are version controlled.

=== Optional CPU voice and persistent browser

Run `bash scripts/setup-cpu-voice.sh` to install the pinned Python runtime and verify the downloaded model checksums. Run `bash scripts/start-voice-service.sh` on Linux with a user systemd session. The service binds to loopback port 8104, uses four CPU inference threads, and is limited to 1 GB of memory and four CPU cores. Configure `LOCAL_TTS_URL=http://127.0.0.1:8104`, `LOCAL_TTS_VOICE=af_heart`, and `LOCAL_TTS_SPEED=1.06`. Other supported voices are `af_bella`, `bf_emma` and `bf_isabella`.

Run `bash scripts/start-web-service.sh` for a browser server that survives closing the launching terminal. These transient user services last for the current user session; they do not install a boot service. Stop them with `systemctl --user stop nodie-web nodie-voice`. Restart the browser server after changing `.env`.

== Optional speaker recognition (home testing)

Install Python 3 with venv support and FFmpeg, then from the repository root:

[source,bash]
----
python3 -m venv .venv-recognition
.venv-recognition/bin/pip install -r recognition/requirements-speaker.txt
python3 scripts/setup-speaker-models.py
bash scripts/start-speaker-service.sh
----

The service binds only `127.0.0.1:8106`, uses two CPU threads, and verifies model checksums at startup. It does not enable the microphone. In desktop Settings, enable _Recognise speakers during conversations_, then enable the mic normally. Recognition settings apply immediately. Rename or forget profiles in the same panel. The browser uses the same local profiles; manage them through desktop Settings.

Model downloads are separate from Nod.ie's MIT source. The Reverb segmentation weights use the https://github.com/revdotcom/reverb[Rev Model Non-Production License], permitting personal testing/research/evaluation in nonproduction environments. The downloader saves its full license and attribution beside the weights. CAM++ comes from https://github.com/modelscope/3D-Speaker[3D-Speaker], with ONNX exports distributed by https://github.com/k2-fsa/sherpa-onnx/releases[sherpa-onnx]. Review model terms before deployment beyond home testing. No model binaries or personal profiles belong in Git.

=== Unmute speaker integration

Install and start the speaker service from the speaker-diarization instructions first. Enable recognition in Settings > People; it is disabled by default.

Run `python3 unmute-service/prepare-backend.py /path/to/unmute --with-speakers`. This prepares memory/privacy adapters, speaker schemas, exact-clock audio windows and word-end propagation together. Set `NODIE_SPEAKERS_DIR` to this branch’s `unmute-service` directory and append `compose.speakers.yml` after the other backend Compose overlays. Recreate only `unmute-backend`.

Without this backend overlay, older Unmute ignores the new field; speech continues but identity hints do not reach the model. Browser-only recognition is not exposed by this change. Raw audio remains in memory and is not retained.

== Window and directly addressed voice controls

For an always-on TV PC with the package installed, launch `/usr/bin/nodie --fullscreen --keep-awake`.
From a checkout, use `npm start -- --fullscreen --keep-awake`.
`--fullscreen` selects TV mode at startup: a normal (non-dock) window stays fullscreen.
Escape, Restore controls and voice restore requests do not leave TV mode. If the
window manager leaves fullscreen, Nod.ie re-enters it. Quit and restart without
`--fullscreen` to return to compact mode. Add `/usr/bin/nodie --fullscreen --keep-awake` to desktop login autostart
(use `Exec=/usr/bin/nodie --fullscreen --keep-awake` in a desktop entry)
to restore the packaged TV display after signing in; it does not enable automatic login.
`--keep-awake` inhibits display sleep while the desktop process runs, using one
idempotent blocker that is stopped on quit.

Nod.ie runs as a single instance. A second launch always shows and focuses the
running window and applies `--keep-awake` if supplied. Forwarding `--fullscreen`
to a compact instance does not change modes: it logs and, where desktop notifications
are supported, displays "Restart Nod.ie with --fullscreen to use TV mode".
For an instance already in TV mode, it simply focuses the window. Later launches
without flags do not disable TV mode or keep-awake.

Without `--fullscreen`, the existing compact behaviour is unchanged; Linux uses
`type: 'dock'` to avoid KWin panel avoidance and resize drift. Presentation changes
retain the same window and renderer, preserving microphone state and conversations.

The desktop has small Full screen / Restore and Minimize to system tray controls centred on the upper-right arc of the avatar boundary. The fullscreen camera preview remains clipped and positioned inside its own control. Full screen presents the enlarged avatar with a dark background and bottom controls; outside TV mode, Escape restores the previous compact position and size. Hiding does not end the conversation. Tray click or the existing show shortcut reopens it.

Directly address Nodie's name for voice controls: natural variants of fullscreen, restore, hide/minimize, show/open, speaker mute/unmute and microphone stop are supported. Overheard keywords, quoted commands, hypothetical discussion and negated window commands do not activate them. This is a bounded intention parser, not unrestricted voice automation. Stop talking means persistent speaker mute, as requested; it does not stop microphone capture. A hidden app can hear an addressed open request while the microphone remains enabled. Once listening is stopped, use the tray or hotkey to enable it again. No secondary always-listening wake-word microphone is opened.

Known people are resolved from names and nicknames in the microphone transcript using a bounded private index. Phonetic variants and ambiguous first names are candidates requiring clarification or spelling; they are never automatically saved or merged. Only matched person facts are supplied to the conversation, without embedding vectors. Cold lookups wait up to 1.5 seconds on the response path and complete privately under a serialized MCP transport.

Directly addressed local controls confirm through the resulting window or mute state. Their model reply is suppressed because the model has not received the local action result. Outside TV mode, Escape is registered while the fullscreen window is visible and released when hidden or restored. In TV mode, Escape is ignored.

The event journal defaults to 30-day retention. Settings provides refresh, retention selection and clear; fullscreen Debug toggles a separate in-memory stream. Backend deployment requires `NODIE_EVENTS_DIR=$HOME/.config/nodie/events` as a read-only mount for dated recall.

The same optional read-only events-directory mount carries a compact Bitcoin/Lightning status snapshot. Desktop refreshes fixed read-only metrics every 30 seconds; Unmute supplies them only on node questions and rejects snapshots older than 60 seconds. The voice container receives no Docker socket, wallet credentials, payment tools or channel-management tools. Camera context does not block this fixed read-only reference.

Append `-f unmute-service/compose.events.yml` to the backend Compose overlays to enable the optional read-only journal/node bridge. Create the events directory as the desktop user with mode 0700 before recreating the backend; the bind refuses to create a missing host directory. Files are 0600, so the backend must run as that UID or as container root. A different non-root UID receives unavailable context rather than changing permissions. The journal records the desktop system timezone, which the backend uses by default (UTC for older journals without timezone metadata). To override it, set the same IANA `NODIE_TIMEZONE` for desktop and Compose.

The Unmute Compose overlay requires `LLM_MODEL` to name an installed model with image support; it no longer silently selects a workstation-specific model alias. Pass your configuration with Compose's `--env-file` or export the variable. `OLLAMA_NUM_CTX` defaults to 8192 and may be overridden to fit the model and hardware.
